# 视觉与交付验收

验收随任务风险和用途选择；不强迫简单展示物走完整制造流程，但用户要求的质量不能用“工具跑完”代替。

## 看图闭环

1. 修改前看整体，记住要验证的比例、接口或缺陷。
2. 修改后获取真实图片并用宿主图像能力查看。先整体低分辨率，需要时局部裁剪；同机位复看才能判断改动影响。
3. 检查主体是否可见、有没有被裁掉、关键部件是否存在、比例/轮廓/孔/连接关系是否正确。画面太远、黑屏或主体太小应重取有效画面。
4. 缺陷写明对象、位置和现象，修完用原机位复验。参数搜索结果用另一条通路复核。

文字回执、hash、PNG 路径证明产物生成，不证明看过画面。不能读图时明确视觉未验收；图像缩略图不能支持精密尺寸结论。

## 数字检查

| 要求 | 可用证据 | 容易误判的地方 |
|---|---|---|
| 包络/关键尺寸 | `audit_measure`，世界坐标顶点复算 | Object.dimensions 不等于旋转后的世界 AABB；确认单位 |
| 网格健康 | `audit_mesh` / `audit_scene` | 读 state/verdict 与检查覆盖；自交跳过、法线未知不能给 pass；未求值网格与应用修改器结果分清 |
| 装配接口/浮空/干涉 | asm_scan/asm_gate、connectivity/clearance | 设计接触可能有多分量；AABB 交叠是粗筛；隐藏允许交叠按规格处理 |
| 参考图外形 | 同机位 visualreport、逐视轮廓+关键特征 | IoU 高不能证明内部特征/深度/材质正确 |
| 材质/UV/贴图 | material_scan/uv_stats 与真实渲染 | 非空材质不等于贴图随包；过程材质按目标格式烘焙 |
| 交付完整性 | deliver_verify、文件清单/hash、重新导入 | 只有原场景正确不能证明导出正确 |

具体 op 参数从 catalog/help 取。gate 的顶层以 `verdict` 为准，嵌套门看各自 state/coverage；`ok` 不是质量判据。缺来源、跳过门、分辨率不足、依赖降级都应保留原结论。任务要求强制门时，用 `gate_preflight/checkpoint/deliver`，以及 `deliver_export(require_gate=true)`；fail 或 degraded 就补修或报告受限。

## 最终交付

提供用户要求的 `.blend`、导出/图片/视频与必要 manifest；核对文件存在、非空、格式、单位、贴图和目标对象。关键导出在干净会话重新导入或用交付验证器检查，不覆盖当前工作场景。

回执保持简短：

```text
产物：<实际文件路径>
已验：<已查看视图 + 尺寸/网格/装配门与结果>
证据：<图片/JSON/清单路径，必要时job/session>
限制：<未验项目/降级原因/待用户判断；无则写无>
```

只报告真实运行覆盖的宿主、平台和路线。GUI doctor pass、无头 see 出图、MCP 发现工具、真实宿主完成任务是不同证据，不能互相替代。
