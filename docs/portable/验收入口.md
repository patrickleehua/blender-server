# 验收入口

每一层分别记录结论。只认当前版本、当前宿主与真实运行产物；自动化检查通过不能替代 Blender 或模型完成任务。

| 层级 | 执行/检查 | 通过证据 |
|---|---|---|
| 独立包 | `npm --prefix packages/blender-agent test`；`npm --prefix packages/blender-agent pack --dry-run` | 共享核心/合同/打包检查通过；包内存在 runtime、addon、Skill、安装器；不含临时环境和上游checkout |
| 项目安装器 | `node scripts/portable-setup-selftest.mjs` | 预览零写、安装幂等、既有配置保留、冲突零写、卸载保留修改与产物、包布局定位、路径逃逸拒绝 |
| Skill 格式 | skill-creator `quick_validate.py skills/blender-agent` | 格式通过、references可访问；这不是行为验收 |
| MCP 协议 | 真实 stdio initialize → tools/list → tools/call | 15工具的标准Schema，响应正确，图片是原生image block，stdout不混日志 |
| GUI | doctor + see | kind=ok，实际看到当前场景图片，addon版本/协议符合 |
| 无头 | worker start → exec → see → stop | 同一session内状态持续，真实图片与代码结果，干净停止 |
| CLI 状态 | backend start → 两条call → status → stop | 同port/workdir复用同一worker；服务归属正确，无错误清理其他进程 |
| CLI 租约 | 同一 `--holder` 的 lease→写入→release；另一holder写入；无holder lease | 本会话跨进程可写/可释放；另一holder返回409；无显式身份返回EXPLICIT_HOLDER_REQUIRED |
| Claude/Codex | 在独立项目加载项目Skill+MCP，实际执行场景任务 | 宿主日志表明真实工具调用、真实图片观察、尺寸/文件验证与交付，而非仅复述指令 |

## 两个宿主的任务模板

在隔离的测试项目安装 Skill 与 MCP，明确输出目录，保留宿主版本、模型、推理档位、启动参数、时间和日志。不要用 mock 后端结论代替真实宿主运行。

> 使用 blender-agent Skill。先 doctor、查 catalog，再用一个独立 worker 创建边长 20mm 的方块，不改 GUI 用户场景。保存到测试项目 outputs/ 的新 blend 文件。实际查看一张图片，独立量测世界坐标包络，确认三边均为 20mm。交付图片、blend、量测JSON与简短验收结论；结束停止自己的worker。发现超时先查状态，不要自动重放写入。

再做一个不同任务验证 Skill 的判断：给一张没有尺度来源的参考图，要求还原白模。宿主应保留相对比例假设，不能凭空给毫米，也不能用“渲染成功”代替打开图片。若要验 GUI，使用独立测试文件，并明确任务授权，避免污染生产场景。
