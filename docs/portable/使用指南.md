# Blender Agent 使用指南

Blender Agent 把同一套 Blender 能力交给 Claude Code、Codex 与其他支持 MCP 的宿主。Skill 负责工作方法，TypeScript 核心负责调用、超时、后端归属和回执，Python 引擎负责实际 Blender 操作；宿主继续负责模型推理、权限和任务会话。

**默认先用 GUI，没窗口或需要批处理时再用无头 worker。** 这是独立工具工程；不需要安装其他 agent harness，也不用配置旧插件宿主。能启动 MCP、能发现工具、能出图和能完成业务任务是四种不同证据。

## 1. 准备与安装

需要 Node.js **22+**、npm，以及另行安装的 Blender **4.x / 5.x**。Python 使用 Blender 自带解释器，不需要用户另装系统 Python、uv 或 pip。历史 MVP 实测 Windows 上 Blender **4.5.15 / 5.0.1 无头**与 **4.5.15 GUI**，具体制品与范围见[验收报告](../acceptance-report.md)；不能代替新入口的验证。Linux/macOS 示例是配置方法，尚无本项目真实机器验收记录。跨版本材质/节点 API 仍要按任务实测。

`@blender-agent/bridge@1.0.0` 尚未公开发布到 npm；当前使用源码构建或本地 tarball。仓库当前为私有，克隆需相应 GitHub 权限：

```text
git clone https://github.com/patrickleehua/blender-server.git
cd blender-server
npm --prefix packages/blender-agent ci
npm run build
node packages/blender-agent/dist/cli.js help
node packages/blender-agent/dist/cli.js help install
```

构建产物把独立运行所需 runtime、addon、Skill 和安装脚本带入包。发布前可以本地打包，不需要先发布 npm：

```text
npm run pack
npm install -g ./release/blender-agent-bridge-1.0.0.tgz
blender-agent help
blender-agent install --help
```

`npm run pack` 在 `release/` 生成 `.tgz` 与 `manifest.json`。收到现成 tarball 的使用者从 `npm install -g <包路径>` 开始即可，不用编译，也不需要源码仓库；仍需 Node、Blender 与 npm 运行依赖。不要用临时 `npx` 缓存路径生成长期 MCP 配置。

以下 `node packages/blender-agent/dist/cli.js ...` 是源码入口；全局安装后可直接替换为 `blender-agent ...`。源码入口需要保持仓库目录位置不变。维护者打包、登录和将来发布 npm 的步骤见[本地分发](../distribution.md)。

## 2. 项目接入 Claude Code / Codex

安装器只写指定项目，不改全局配置。首次接入保留已有文件；升级只替换 manifest 记录且未被用户修改的安装器自管文件。先预览，确认输出后加 `--apply`：

```text
blender-agent install --project "C:/my project" --host both --port 19877 --addon-port 19876 --worker-port 19879 --dry-run
blender-agent install --project "C:/my project" --host both --port 19877 --addon-port 19876 --worker-port 19879 --apply
```

项目目录必须已存在；`--project` 默认当前目录，`--host` 默认 `both`，省略 `--apply` 时只预览。只装一个宿主可选 `--host claude` 或 `--host codex`。非自动探测 Blender 环境加 `--blender <Blender可执行文件绝对路径>`，可用 `--workdir` 指定工作目录。含空格路径加引号；`help install` 或 `install --help` 查看参数。

源码入口等价写法为 `node packages/blender-agent/dist/cli.js install ...`。旧 `node scripts/portable-setup.mjs --project <项目目录> ...` 保持兼容，独立包同样保留 `node <已安装包绝对路径>/scripts/portable-setup.mjs ...`；旧脚本需要显式 `--project`。

安装位置：

| 宿主 | Skill | 项目 MCP 配置 |
|---|---|---|
| Claude Code | `.claude/skills/blender-agent/` | `.mcp.json` |
| Codex | `.agents/skills/blender-agent/` | `.codex/config.toml` |

两个位置内容相同。Claude 中可用 `/blender-agent`，Codex 中可用 `$blender-agent`；也允许宿主自动发现。其他支持 Agent Skills 的宿主，按其项目目录约定复制整个 Skill 文件夹，并连接同一个 MCP 服务。

如果项目已经有 MCP 配置，安装器保留它，只生成 `.blender-agent/config-candidates/claude.json` 或 `codex.toml`。把候选中的 `blender-agent` 条目审阅合入现有项目配置。已有同名 Skill 内容不同时安装器会列出冲突并停止，**不会部分覆盖**；先保留自己的改动，再选择新的项目目录或处理差异。

升级工具包后，使用新包的 `blender-agent install` 对原项目重新执行同一组参数，先 `--dry-run` 再 `--apply`。计划中的 `update` 表示文件仍等于上次安装记录，可以安全更新；`conflict` 表示有用户修改或原本不归安装器管理，整次安装保持零写。修改过的 Skill 或加入其他 server/设置的自管宿主配置都不会被覆盖，需要先备份并处理差异；手工合入的已有配置仍由用户维护。升级后重新加载宿主，卸载继续只删除与最新 manifest hash 一致的文件。

配置引用当前 Node 与 CLI 的绝对路径，换机器或移动工具目录后要重新生成候选。不要把个人机器路径当作团队统一配置直接提交。项目自己的全局忽略规则也由项目管理；安装器不修改 `.gitignore`、`AGENTS.md` 或 `CLAUDE.md`。

MCP 配置基本形状如下，实际路径与端口以安装器生成的候选为准：

```json
{
  "mcpServers": {
    "blender-agent": {
      "command": "/absolute/path/to/node",
      "args": ["/absolute/path/to/bridge/dist/cli.js", "mcp", "--port", "19877", "--addon-port", "19876", "--worker-port", "19879", "--workdir", "/absolute/project/.blender-agent/runtime"]
    }
  }
}
```

Codex 对应：

```toml
[mcp_servers.blender-agent]
command = "/absolute/path/to/node"
args = ["/absolute/path/to/bridge/dist/cli.js", "mcp", "--port", "19877", "--addon-port", "19876", "--worker-port", "19879", "--workdir", "/absolute/project/.blender-agent/runtime"]
startup_timeout_sec = 60
tool_timeout_sec = 900
```

启动或重新加载项目宿主，按宿主提示信任项目并允许此 MCP。Codex 只在受信任项目加载项目配置；不要为接入而全局关闭权限。可用 `config --host claude|codex` 单独打印配置片段。

## 3. 启动与 doctor

Windows PowerShell 示例，在仓库根目录；将第二行替换为实际可执行文件，含空格的路径保留引号：

```powershell
$agent = (Resolve-Path packages/blender-agent/dist/cli.js).Path
$blender = 'C:\Program Files\Blender Foundation\Blender 4.5\blender.exe'
$work = Join-Path $PWD '.blender-agent/runtime'
node $agent backend start --port 19877 --addon-port 19876 --worker-port 19879 --workdir $work --blender $blender
node $agent doctor --port 19877 --addon-port 19876 --worker-port 19879 --workdir $work --blender $blender
node $agent backend status --port 19877 --addon-port 19876 --worker-port 19879 --workdir $work --blender $blender
```

Linux/macOS 使用相同 CLI 参数，Blender 路径例如 `/usr/bin/blender` 或 `/Applications/Blender.app/Contents/MacOS/Blender`。环境变量 `DSH_BLENDER_EXE`、`DSH_BLENDER_WORKDIR` 等是复用引擎的兼容配置接口；产品入口使用上面的显式参数即可，优先级和边界见 [架构与配置](架构与配置.md)。

**CLI 场景操作先显式 `backend start`，并一直使用同一组端口 / workdir / Blender 参数。** 以下调用没有 persistent 后端会返回 `PERSISTENT_BACKEND_REQUIRED`：do/see/watch；plan 非 catalog；worker 除 list/status；loop target=session；headless；job start；viewport start/restart。catalog、doctor 和状态查询可独立使用。

MCP 按已注册活跃客户端管理自动后端：一个宿主关闭或死亡，其他活跃宿主的场景继续保留；最后客户端离开才清理。显式启动的 persistent 后端在无客户端时仍保留。显式 stop 遇到其他客户端返回 `BACKEND_IN_USE`，先关闭其他客户端，再停止自己的后端。

端口被旧服务占用时不接管、不杀进程，换一组可用端口。上面的 19877/19876/19879 是隔离示例；默认分别是 9877/9876/9879。多实例也要隔离工作目录，所有调用复用同一组端口。

### CLI 场景身份与写租约

CLI 每条命令都是新进程。do/see/watch、worker 除 list/status、plan 带 session 的非 catalog 操作、loop target=session，以及 lease/release，都必须带稳定的 `--holder <本次会话id>`；也可在当前工作终端设置 `BLENDER_AGENT_HOLDER`。缺失返回 `EXPLICIT_HOLDER_REQUIRED`。同一工作流保持相同 holder 与 worker/session 名；不同工作流使用不同 holder 和 worker 名。跨 holder 操作同名 worker 返回 `WORKER_OWNED` / HTTP 409，先查 list/status，不强抢。

例如已启动后端、GUI doctor 已通过时，在 PowerShell 中准备 `lease.json` 为 `{"op":"lease"}`、`release.json` 为 `{"op":"release"}`，`change.json` 为本次已授权修改的 `blender_rt_do` 参数，然后：

```powershell
$bridgeOptions = @('--port', '19877', '--addon-port', '19876', '--worker-port', '19879', '--workdir', $work, '--blender', $blender, '--holder', 'organizer-session-a')
node $agent call blender_viewport --file lease.json @bridgeOptions
node $agent call blender_rt_do --file change.json @bridgeOptions
node $agent call blender_viewport --file release.json @bridgeOptions
```

每个并行 agent 用不同 holder，不要把示例值变成所有会话共用的身份；遇到 `409 leased` 查 `who`，不强抢。MCP 默认在一个服务进程里保持自己的 holder，项目配置不需要硬编码统一 holder。

### GUI 路线

安装并启用随包 `addon/dsh_blender_bridge.py`（源工程位于 `bridge/addon/`，独立包位于 `assets/addon/`）。在 Blender 的 3D 视图按 `N`，打开 Bridge 面板，将端口设置为本项目 `--addon-port`（示例 19876），再 Connect。只用此配套 addon v1.10+ / protocol 11；旧的 MCP for Blender addon 与这套协议不兼容。

在宿主调用 `blender_viewport(op="doctor")`，应得到 **`kind=ok`**；再 `blender_rt_see(max_size=560)`，实际查看返回图片。仅 `/health` 通过或进程启动不能说 GUI 已装好。

只有 doctor 明确 GUI 不可达时才自动走无头 worker。GUI 忙碌、暂停或状态不明时不会切到另一个场景；等当前操作完成或处理暂停后再取图。`full=true` 的完整 UI 截图需要真实 GUI，不能用无头渲染替代。

N 面板支持按**多选 / 集合**读取 Blender 原生选择，也有“暂停 AI 操作”；编辑模式点/线/面等子选择由 addon 报告。旧的“送入 DSH 草稿”按钮属于上游宿主专用桥，独立 Claude/Codex 入口不把它当作已实现的聊天注入；当前以工具读取 selection 为准。

### 无头备用路线

无 GUI 不需要 addon，在宿主调用：

```text
blender_rt_worker(op="start", name="smoke")
blender_rt_worker(op="see", name="smoke")
```

实际查看回传图片，随后 `blender_rt_worker(op="stop", name="smoke")`。纯无头路线 doctor 的 GUI/bpy 往返不可达属预期，不能伪称 GUI doctor 已通过。

CLI 等价调用，把 UTF-8 JSON 保存为 `worker-start.json` / `worker-see.json`，依次执行：

```json
{"op":"start","name":"smoke"}
```

```json
{"op":"see","name":"smoke"}
```

```text
node packages/blender-agent/dist/cli.js call blender_rt_worker --file worker-start.json --holder smoke-session-a --port 19877 --addon-port 19876 --worker-port 19879 --workdir <同一工作目录> --blender <同一Blender路径>
node packages/blender-agent/dist/cli.js call blender_rt_worker --file worker-see.json --holder smoke-session-a --port 19877 --addon-port 19876 --worker-port 19879 --workdir <同一工作目录> --blender <同一Blender路径>
```

MCP 原生显示 image；CLI JSON 可能包含 base64 图片，实际看图使用回执中的本地图片路径或宿主读图能力，不要把大段 base64 再发给模型。

do 已执行成功但取图失败时，回执仍为 `isError=true`，同时标记 `executionCompleted=true`。此时只重试 see，禁止重放 code。headless/job 等工具的 `args` 支持字符串数组；含中文、空格或引号的参数优先逐项传入数组。worker 的 see/watch 均可用 `view_size` 指定图片大小。

## 4. 让 agent 开始工作

可复制提示词，替换目标与输出位置：

> 使用 blender-agent Skill，在当前 Blender 场景创建一个桌面收纳盒。先查看当前场景、单位和图片；保留已有对象。外尺寸 200×120×80 mm，壁厚 3 mm，输出到项目 outputs/organizer/。先做白模确认比例，再做圆角和材质，每次关键修改后实际看图。交付可编辑 blend、GLB、两张预览和验收记录；不要覆盖已有文件。需要影响外观的选择时给 A/B/C 选项。

其他常见入口：

| 目标 | agent 使用的能力 |
|---|---|
| 按参考图建模 | 实际看图 → img_digest/probe → 有尺度来源才标定 → 建模 → 同机位视觉与尺寸验收 |
| 检查装配穿模/浮空 | 清单与接口 → asm_scan → safe repair → asm_gate → 导出 |
| 白模给视频模型参考 | blockout → refsheet 四视图/JSON → 可选转台，核对实际视频文件 |
| 长渲染/批量操作 | job/headless + 句柄回收；超时先查状态，禁止盲目重放写入 |

不熟悉操作名时用 `catalog` / `catalog --family audit`，不要编造参数。`tools` 列出 15 个标准工具与输入 Schema。输出重点读 verdict、coverage、warnings 和实际产物路径，`degraded` 不等于通过。

## 5. 验收与卸载

先按 [验收入口](验收入口.md) 分别验证工具发现、实际 Blender、视觉闭环与宿主任务。真实宿主、操作系统与 GUI/无头覆盖范围要逐项记录，不承诺没跑过的平台“完美兼容”。

卸载前保存模型，停止自己持有的 worker 和 backend：

```text
node packages/blender-agent/dist/cli.js backend stop --port 19877 --addon-port 19876 --worker-port 19879 --workdir <同一工作目录>
node packages/blender-agent/dist/cli.js uninstall --project <项目绝对路径> --dry-run
node packages/blender-agent/dist/cli.js uninstall --project <项目绝对路径> --apply
```

全局安装后使用 `blender-agent uninstall --project <项目目录> --dry-run`，检查后改为 `--apply`；`--project` 默认当前目录。原 `node scripts/portable-setup.mjs --project <项目目录> --uninstall ...` 与独立包内脚本继续兼容。

安装器只删除 manifest 记录且 hash 未变化的文件，保留用户修改、工作目录和模型产物；空目录会保留。手工合入既有 MCP 配置的条目需手工移除 `blender-agent` 部分。清理所有引用该工具包的项目配置后，再执行 `npm uninstall -g @blender-agent/bridge` 删除全局工具包；源码路线则保留或自行归档仓库。卸载项目接入不会卸载 Blender。

项目接入的官方说明：[Codex Skills](https://developers.openai.com/codex/skills)、[Codex 配置](https://developers.openai.com/codex/config-reference)、[Claude Skills](https://code.claude.com/docs/en/skills)、[Claude MCP](https://code.claude.com/docs/en/mcp)。
