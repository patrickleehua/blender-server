# 独立重构设计

目标是让 Claude、Codex 和其他 MCP 宿主在真实 Blender 中完成“观察 → 修改 → 复核 → 保存/导出”，同时让 CLI 能使用同一套能力。宿主继续负责规划和交互，本项目不另建 Agent Harness。

根据用户的补充要求，本项目重新 `git init`，不沿用上游仓库作为开发工程。上游仅作为固定版本的只读参考；产品包不依赖 `.upstream`，不加载原 DSH 插件，也不要求 DSH 的构建或安装环境。

## 责任边界

| 模块 | 负责什么 |
| --- | --- |
| Skill | 何时使用、怎样选能力、建模闭环、验收和失败处理 |
| CLI / MCP | 输入输出与宿主协议；共用核心实现 |
| TypeScript 核心 | 参数校验、HTTP 映射、后端归属、超时、图像回传、进程清理 |
| 工具合同 | 独立维护 15 个工具的 JSON Schema；目录按需展开能力族 |
| Blender 执行引擎 | 复用稳定的 Python 几何/量测/装配/验收能力与本地运行通道 |
| Blender addon | GUI 会话的主线程执行、视口与原生选中 |

控制层使用 TypeScript 并编译为 JavaScript；建模留在 Blender 自带 Python 中。此能力无需额外系统 Python/uv，也不需要为适配宿主重写稳定的几何算法。安装和验证脚本使用低依赖 `.mjs`。新工具包提交自己的 npm 锁文件，使用 `npm ci` 固定依赖。

## 关键契约

- CLI 和 MCP 调用同一核心，不分别维护建模逻辑。MCP 图像必须返回标准 image 内容，不能仅给路径后宣称已观察。
- GUI 用户的已有场景与无头测试隔离；CLI 连续操作使用显式持久 backend，MCP 会话管理自己创建的后端与 worker。
- 自动启动前核对后端身份、版本与工作目录。端口被其他服务占用时明确失败，不夺取和误接管。
- 写请求失败后不自动重放；超时不等于执行没有发生。先查状态/产物，再决定后续动作。
- 文件级快照保护拓扑改动；对象级 mark 不冒充完整撤销。`pass / fail / degraded` 保留原语义。
- 安装限于指定项目目录，默认 dry-run；不覆盖已有宿主设置，不写入全局配置。
- 独立包包含运行资产、合同、Skill 和必要许可，不能靠开发目录偶然存在的文件运行。

## 验证边界

以 `docs/acceptance-scenarios.md` 的行为预期为准。真实宿主必须按用户指定模型和 medium effort 执行；另由 Blender 脚本检查保存文件和导出物。操作系统兼容声明与实际运行证据分开记录，CI 配置存在不等于已跑过三系统。
